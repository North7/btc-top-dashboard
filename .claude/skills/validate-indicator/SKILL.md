# 新指標驗證

使用者不是工程師：全程用繁體中文、白話說明，結論先講，數字用表格。不要因為指標在社群很紅就預設它有用，也不要因為截圖上畫了漂亮的標記就相信（那些通常是事後挑的點）。

## 1. 先搞清楚指標是什麼

- 寫出計算公式（例如 STH-NUPL = 1 − 短期持有者成本 ÷ 價格）。截圖上的說明若有筆誤（例如「< 1」其實應為「< 0」）要指出。
- 判斷它屬於哪一類，以及和現有指標的關係：鏈上估值、持有者行為、資金流、槓桿、情緒、價格結構、動能。
  很多指標其實是現有指標或價格動能的變形（例如 SSR 震盪指標 ≈ 價格相對 200 日的偏離）。

## 2. 資料能不能取得（決定能做到哪一步）

Tidemark 是公開網站，計分用的資料必須**同時**符合：免費、有完整多週期歷史（至少涵蓋 3 次頂部與 3 次底部）、授權允許公開。

- 先查能否由現有資料自己算：`data/raw/` 有 Coin Metrics（價格、市值、實現市值、供給、發行量、算力）、DefiLlama 穩定幣、ETF 流量、資金費率、未平倉量、基差、Coinbase 溢價、恐懼貪婪、Bitstamp 日 K。
- 外部來源（Glassnode、CryptoQuant、CheckOnChain、BGeometrics、Look Into Bitcoin 等）：用瀏覽器實際打開確認是否免費、歷史多長、有沒有 API、條款是否禁止再散布。
  BGeometrics 免費 API 只有近 4 年且禁止公開再散布；Glassnode 多數持有者指標需付費。
- 不符合條件的，最多只能「本機研究」或放進中期狀態頁的「外部參考」（`btc_top/page.py` 的 `REFS`，只放連結與自寫說明）。
  外部資料只能放在 scratchpad 研究，**不可寫入倉庫**。

## 3. 跑驗證腳本

在倉庫根目錄執行（只讀資料，不寫檔）：

```bash
.venv/bin/python .claude/skills/validate-indicator/validate.py --name "名稱" --expr "公式" [--transform z200|ma200|log] [--above X] [--below X] [--start 2019-01-01]
```

`--expr` 可用 `ind`（網站指標表）、`raw`（原始資料）、`cm`（Coin Metrics 欄位）、`price`、`np`、`pd`。
外部 CSV 用 `--csv 檔案 --col 欄位`。腳本輸出：資料範圍、週期頂部與中段假頂（2019-06、2021-04、2024-03）讀數與同輪比較、
週期底部與中段假底（2019-12、2020-03、2021-07、2024-08）讀數、本輪低點（樣本外）、與現有指標的相關性、觸發事件之後的報酬。

需要更細的測試（逐輪擬合、加入計分後頂部／底部訊號的變化、策略回測）時另寫 scratchpad 腳本，沿用 `btc_top.scoring` 的函式。

## 4. 判斷標準

| 問題 | 通過條件 |
|---|---|
| 頂部 | 同一輪中，真頂部讀數高於中段假頂（2021-04、2024-03 是最常見的陷阱）；或加入計分後，真頂部的頂部訊號變高、假頂沒有變高 |
| 底部 | 三次週期底部都比中段假底更極端；本輪低點（2026-06-30）的表現只當樣本外參考 |
| 重複性 | 和現有計分指標的 \|相關\| < 0.7；否則只是重複計分 |
| 事件 | 至少 8 次事件、且和「同期所有日子」的差異在不同年份都成立；少於 8 次一律視為證據不足 |
| 前視 | 計算不可用到未來資料（全樣本擬合、事後才知道的頂部日期都算前視）；逐輪檢驗時只用當時已發生的頂部與底部 |

鐵律（來自 CLAUDE.md）：
- 參數只依過去的頂部、底部與假訊號決定，**不可為了讓 2026 年結果好看而調整**。
- 週期策略規則已在 2026-10-06 定案，驗證結果不可拿來改策略門檻。
- 研究過的結論不要推翻重來：48 個指標研究、私人版持有者指標試算、SSR 實測等結果記在記憶檔；先看記憶再動手。

## 5. 回報格式

1. **一句話結論**：採用／只當參考／不採用，以及最主要的原因。
2. **能不能取得**：免費來源在哪、能不能放進網站。
3. **實測表格**：頂部、底部、相關性、事件報酬（挑重點，不要整份貼上）。
4. **要打折看的地方**：截圖的說法哪裡是事後挑點、哪些條件要事後才知道（例如「牛市中」）。
5. **下一步選項**：例如放進外部參考、只在本機觀察、或（通過驗證時）請使用者同意後加入計分。

加入計分或改變頁面一定要先徵求使用者同意；通過後要同步更新 `btc_top/scoring.py`、README、CLAUDE.md，並把結論寫進記憶。
不採用的指標，若使用者常會看到（社群熱門），建議放進「外部參考」並標「已實測・未採用」與一句實測結論。
